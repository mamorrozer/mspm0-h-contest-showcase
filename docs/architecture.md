# 系统架构与关键设计

本页是完整竞赛项目的高层设计说明。对应的完整应用固件没有随本精选版公开；下文说明的是项目中的系统职责与设计行为，不表示所有功能都能从本仓库源码直接复现。实机验证状态以[验证记录](validation.md)为准。

## 职责划分

| 子系统 | 输入 | 项目中的设计职责 | 异常处理方向 |
|---|---|---|---|
| MSPM0 主控 | 循迹传感器、K230 UART、AXIS6 UART、按键与蓝牙命令 | 任务状态机、底盘控制、摆杆控制、安全出口与遥测 | 失去有效观测时停止或退化到已定义的安全行为 |
| K230 视觉端 | 摄像头图像 | 钢球目标提取并输出结构化观测 | 主控按帧有效性和观测时效判断数据是否可用 |
| 底盘 | 主控 PWM 与方向输出 | 差速循迹与终点停车 | 急停入口与终点锁存停车 |
| 摆杆机构 | 主控步进脉冲与方向输出 | 调平和钢球位置控制 | 对位置命令限幅，停止状态保持输出安全 |
| AXIS6 | 加速度/角速度观测 | 辅助运动状态判断；受限前馈不替代视觉反馈 | 数据超时后禁用辅助量，主控制路径继续按自身观测运行 |
| OLED 与蓝牙 | 主控状态 | 显示状态、调试命令和回传日志 | 显示/通信工作不应阻塞运动控制 |

## 控制路径

主控软件将不同工作放在各自的周期或事件路径中：底盘循迹、滚球控制、步进脉冲服务、串口接收和低频显示分别处理。设计中的串口中断收取字节并放入环形缓冲，前台逻辑再解析完整消息；运动控制根据最新有效观测更新输出。该精选仓库未包含完整主控固件，读者无法在此直接复现整车数据流。

步进脉冲属于短周期输出路径，不依赖低频任务延时来产生脉冲。OLED 通过异步 I²C 分页传输，避免在控制循环中等待整帧显示完成。

## 安全与降级

- **人工停止优先：** 完整项目中，按键或调试命令可请求停止当前任务。
- **视觉数据有效性：** 项目设计只在消息格式正确、目标有效且数据未过期时使用视觉反馈。
- **限时退出：** 对等待目标、A 到 B 运行和终点识别设置安全退出条件。
- **辅助量可失效：** AXIS6 输入失效时不沿用旧观测；辅助量归零，视觉闭环按自身数据继续运行。
- **基线可回退：** 对循迹和制动策略保留阶段基线，增强功能逐项叠加并与原结果区分。

## 终点识别设计

起点和终点共用横线，因此系统先确认车辆离开起点区域，再允许终点事件触发。基础判据使用连续黑色传感器图案；增强版本在接近终点时增加连续帧确认，降低车辆斜向通过时漏检的概率。触发后进入锁存主动制动，避免重复检测造成状态抖动。

当前终点增强逻辑有阶段实机结果，但样本数较小，停车偏差缺少逐次尺量；这只说明在该阶段条件下观察到的结果，不证明已达到题目精度指标。

## 设计取舍

1. **先冻结基线，再增加功能。** 传感器、停车和显示问题分开验证，避免多项同时变化后无法归因。
2. **观测与执行分离。** K230/AXIS6 只提供观测；最终控制决策和安全出口由 MSPM0 主控负责。
3. **周期服务与硬时序输出分离。** 控制决策可以按周期运行，脉冲生成继续走短周期定时路径。
4. **按证据限定项目表述。** 阶段候选、独立模块和组合实机验证分别记录。
